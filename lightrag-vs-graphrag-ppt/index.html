03 · LightRAG 组件结构

当前代码体现出“多组件协同检索”

存储组件

Chunk / Entity / Relation

保留原文、实体描述、关系描述和 source_chunks，使答案能追溯到聊天片段。

图组件

NetworkX Graph

把用户、主题词和加权关系组成图，用 rank、weight 和一跳邻域处理关系问题。

社区组件

CommunityReport

通过 Louvain 聚类得到群体级摘要，服务 global 和 hybrid 模式。

向量组件

四类向量索引

chunks、entities、relations、communities 分别建索引，支持多入口召回。

检索组件

local / global / hybrid

低层实体关系和高层社区摘要可以单独使用，也可以合并为混合检索。

增量组件

stable_hash

按内容 hash 复用旧 chunk，降低持续新增聊天记录时的重建成本。

04 · 组件差异矩阵

二者组件上的核心区别

组件LightRAG 侧重点GraphRAG 侧重点用途差别
数据切块组件保留 chunk，并让 chunk 直接参与向量检索和证据回溯chunk 更多作为实体/关系抽取和摘要生成的原始材料LightRAG 更强调原文证据快速召回；GraphRAG 更强调构图前处理
实体组件实体本身带描述、rank、source_chunks，并可被向量命中实体主要是图节点，是社区组织和全局摘要的基础LightRAG 中实体是检索入口；GraphRAG 中实体更像知识图谱骨架
关系组件关系有类型、权重、描述和来源 chunk，可单独向量检索关系主要用于构成图结构和社区内外连接LightRAG 更适合回答具体关系追溯；GraphRAG 更适合分析结构强弱
社区组件社区报告是 high-level 检索入口之一，可与低层结果混合社区报告通常是全局回答的核心素材LightRAG 把社区当作一类证据；GraphRAG 把社区当作全局组织单元
向量组件对 chunk/entity/relation/community 全部建向量索引可结合向量，但核心仍是图社区和摘要层级LightRAG 更依赖多路召回；GraphRAG 更依赖图上聚合
检索组件local、global、hybrid 三种模式按问题切换围绕局部邻域、社区摘要和全局报告组织上下文LightRAG 更灵活；GraphRAG 更偏宏观综合
更新组件代码中明确支持基于 hash 的增量复用图和社区摘要变化后，通常需要更重的重建或重摘要LightRAG 更适合频繁新增数据；GraphRAG 更适合阶段性批处理

05 · 组件流程差异

LightRAG 更像多路检索器，GraphRAG 更像全局组织器

LightRAG 组件流

从问题出发，动态组合证据

Query
 → entity / relation vector search
 → graph neighborhood
 → community vector search
 → source chunks
 → context

重点是按查询意图组装最相关证据，适合交互式问答。

GraphRAG 组件流

从语料出发，先形成全局结构

Corpus
 → entity / relation extraction
 → graph construction
 → community detection
 → community reports
 → global / local answer

重点是把大语料预先组织成层级图谱，适合全局分析和报告。

06 · 阶段性对比

目前形成的核心判断

维度LightRAG：当前代码体现GraphRAG：典型侧重点
主要目标轻量地组合局部关系、全局社区和原文证据组织大规模语料的全局知识结构
组件重心多向量索引 + 图邻域 + 社区证据并行图构建 + 社区发现 + 层级摘要为主
查询方式chunk / entity / relation / community 多入口围绕图、社区和层级摘要进行综合
优势问题关系追溯、增量更新、快速试验跨文档主题、群体画像、全局报告
工程取舍本地可跑、逻辑可控、实现较轻构建成本更高，但全局摘要能力更强

07 · 当前成果

已经可以支持两类典型汇报结论

已形成

LightRAG 适合回答关系型问题

  • 谁和谁互动最密切？
  • 某个用户和哪些主题相关？
  • 某条关系来自哪些原始消息？
  • 数据持续增加时如何增量更新？
已形成

GraphRAG 适合回答全局型问题

  • 整个资料库有哪些主要主题？
  • 不同群体的观点如何分化？
  • 跨文档的共同结论是什么？
  • 如何生成面向管理者的全局报告？
面向当前聊天记录场景：LightRAG 更适合先完成关系探索；GraphRAG 更适合在数据规模扩大后做全局归纳。
