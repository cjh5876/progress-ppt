paper_lightrag.py

这份脚本把群聊消息加工成“可检索的图谱状态”：既保留聊天原文，又用实体、关系、社区和向量索引组织上下文。

阅读对象：paper_lightrag.py　|　汇报重点：函数职责与处理链路

→

核心理解：它不是单一的“聊天搜索脚本”，而是一条离线构建、在线查询的轻量 GraphRAG 管道。

02 · 数据模型

四个 dataclass 是图谱状态的骨架

Chunk

原文片段

保存时间范围、参与者、消息 ID、拼接后的文本与稳定哈希，用作可追溯来源。

Entity

用户 / 话题

统一记录实体类型、名称、描述、来源 chunk 和加权度 rank。

Relation

有向语义关系

保存 source、target、类型、权重、事件统计和来源 chunk。

CommunityReport

社区摘要

保存 Louvain 社区编号、标题、摘要、成员和社区权重。

# 状态的主要组成 state = {"chunks", "entities", "relations", "communities", "G", "node_stats", "vector_indexes"}
03 · 基础工具函数

先把文本变成稳定、可比较的表示

stable_hash

对 UTF-8 文本做 SHA-1，给 chunk 和 relation 生成稳定 ID，支持增量复用与去重。

normalize_vector

按 L2 范数归一化向量；零向量原样返回，避免除零。

char_ngrams

去空白、转小写，产生 2 到 4 字符 n-gram，适配中文短文本与混合文本。

embed_text / embed_texts

使用哈希桶把 n-gram 投影到 384 维，得到轻量稀疏风格向量；批量函数负责堆叠矩阵。

VECTOR_DIM = 384NGRAM 2–4无外部 embedding 服务

04 · 数据预处理

load_messages + make_chunks

load_messages

  • 从 JSON 读取原始消息。
  • 保留有 sender、非空 content 的记录。
  • 排除“系统消息”。
  • 按 timestamp 升序排列，保证后续时间窗口成立。

make_chunks

  • 相邻消息间隔超过 10 分钟时切块。
  • 单块最多 24 条消息。
  • 拼接“时间 + 昵称 + 内容”，保留 msg_ids。
  • 用 stable_hash 识别未变化 chunk，支持增量索引。
消息流 → 时间/数量双重切分 → Chunk(id, hash, start_ts, end_ts, senders, text, msg_ids)
05 · 图谱构建

build_user_directory 到 build_indexes

用户目录

build_user_directory 统计每个 sender 最常见的 display_name，建立 ID↔昵称双向映射。

话题实体

extract_terms 提取中文词/英文词，过滤 STOP_TERMS 与 TOPIC_NOISE。

@目标

extract_at_targets 按昵称长度降序匹配 @昵称，去重并返回用户 ID。

build_indexes 的主循环

遍历每条消息，更新用户统计、来源 chunk 和 NetworkX 图。通过内部 add(a,b,typ,weight) 统一生成 relation_id、累计边权、记录事件次数与来源。

mention × 3.0quote × 4.0adjacent × 1.0co_topic × 0.6

输出什么

每个社区形成一个 CommunityReport，可作为 global 检索的高层上下文。

理解上的关键点

社区不是人工标签，而是由关系权重驱动的结构发现结果；标题与摘要是可读化封装。

07 · 检索准备

build_vector_indexes：四类对象共用一套向量检索接口

01

chunks

原始聊天片段，回答“具体聊了什么”。

02

entities

用户/话题描述，回答“谁或什么最相关”。

03

relations

关系描述，回答“谁和谁有什么联系”。

04

communities

社区摘要，回答“群体层面的主题与结构”。

每个索引保存 ids + matrix；真正查询时由 hybrid_text_search 结合向量相似度与字符词面重合。

08 · 查询逻辑

retrieve 是规则路由 + 混合召回

hybrid_text_search

查询清洗后生成 q-gram；得分 = 0.45 × 非负向量相似度 + 0.55 × 词面重合度。若核心串完整出现在文档中，再增加词面奖励。

问题类型识别

_relation_question、_people_relation_question、_activity_question、_topic_question 先判断意图，再决定召回范围。

三种模式

local 只保留实体、关系、邻域和原文片段　 global 只保留社区摘要　 hybrid 合并低层图谱与高层社区上下文

09 · 结果输出

从图结构到可读答案的辅助函数

related_graph_context

获取选中实体的一跳邻居，去重后输出关系权重和边属性。

_user_relation_context

只保留用户—用户边，并按权重排序，服务于“谁和谁关系最强”。

collect_chunks

按 ID 收集有限数量原文片段，避免上下文无限膨胀。

format_simple_result / format_context

分别提供一句话答案和完整检索上下文，便于 CLI 直接展示或继续喂给下游模型。

retrieve(...) → { simple_answer, low_level, high_level, chunks }
10 · 运行与持久化

main 把离线建库和在线查询接起来

1

index

读取输入 JSON，必要时加载旧 state，调用 build_indexes，保存 pickle 并导出三张 CSV。

2

query

加载 state，调用 retrieve，打印 format_simple_result 的一句话结果。

3

stats

读取 state，输出 source、chunk/entity/relation/community 数量及图节点、边数量。

python paper_lightrag.py index [--input ...] [--rebuild] python paper_lightrag.py query "谁和谁关系最密切" --mode hybrid --top-k 6 python paper_lightrag.py stats
