03

node 属性来源

初始化结构
node = defaultdict(lambda: dict(
  msg=0,
  mention_out=0,
  mention_in=0,
  quote_out=0,
  quote_in=0
))

来源解释

  • msg：每遍历到一条该用户发送的消息就加 1。
  • mention_out：该用户在文本里 @ 别人的次数。
  • mention_in：别人 @ 到该用户的次数。
  • quote_out：该用户发送“引用消息”的次数。
  • quote_in：该用户被别人引用回复的次数。
结论：node 不是外部输入字段，而是从消息遍历过程中动态累计出来的“用户画像统计”。
04

edges 属性来源

@ 提及

文本或引用消息中出现 @昵称，通过 name2id 映射到目标用户。

引用回复

引用消息没有直接携带被引用者时，退化为“回复给最近一位非自己发言的人”。

拍一拍

从消息内容中用正则抽出两个 ID，作为一次 pat 关系。

邻近接话

若与上一条不同发送者的消息时间差不超过 30 秒，则记一次 adjacent。

边权重合成
total =
  mention * 3.0 +
  quote   * 4.0 +
  pat     * 2.0 +
  adjacent* 1.0
结论：edges 是“多种互动证据”的汇总结果，最终以 total 作为建图权重。
05

进入图结构时，节点和边各带什么信息

Node 写入 Graph

G.add_node(uid,
  label=id2name.get(uid, uid),
  msg_count=node_stats[uid]["msg"]
)

只保留发言数 >= MIN_MESSAGES 的活跃用户。

Edge 写入 Graph

G.add_edge(a, b,
  weight=d["total"],
  mention=d["mention"],
  quote=d["quote"],
  pat=d["pat"],
  adjacent=d["adjacent"],
  total=d["total"]
)

只保留双方都活跃且总权重大于 0 的关系。

图不是直接读取 JSON 成品，而是先抽统计，再筛活跃用户，再写入图结构。

用途

  • 辅助定位入口文件、数据流和依赖关系。

  • 提升理解陌生仓库的起步速度。

一句话总结：DeepWiki 更像“项目导航层”，帮助先建立整体认知，再进入代码细节。
